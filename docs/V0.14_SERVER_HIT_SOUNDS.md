# v0.14 Server-wide JujutsuCraft hit-sound controls

Forge 1.20.1 / JujutsuCraft v51 / Easy NPC 7.15.0 / CustomNPCs GBPort.

## Server configuration

In a dedicated server:
`<server>/world/serverconfig/jujutsunpccompat-server.toml`

In single-player:
`.minecraft/saves/<world>/serverconfig/jujutsunpccompat-server.toml`

```toml
[sounds]
    npcHitSounds = true
    playerHitSounds = true
```

* `npcHitSounds = false`: suppress identified JujutsuCraft hit/reaction cues
  played when either Easy NPC or CustomNPCs humanoids are hit.
* `playerHitSounds = false`: suppress those hit/reaction cues when **any
  player on the server** is hit.
* Both settings are **SERVER**, not `CLIENT` or individual NPC settings.
  They default to ON so v0.13 behavior does not change unexpectedly.
* Changes to the TOML should be made with the server stopped, then restarted
  so the current config is loaded and Forge syncs its effective settings.
* Other vanilla hit sounds, cursed technique effects, domain activation,
  music and other JujutsuCraft sounds are not deliberately silenced.

The supported original JJK hit/reaction sound identifiers in ver51:
`jujutsucraft:gacon`, `punch`, `strong_hit`, `critical`,
`crush`, `glass_crash`, `guard`, `guard_just`,
and `guard_sword`.

The server listens to actual incoming `LivingAttackEvent` recipients (to
distinguish a player from an NPC), then cancels a recognized JJK hit sound
played at the target within three ticks and 2.5 blocks. This cancels
the audio on the SERVER before it reaches any nearby players.

For JJK's own client-local sound branch, v0.14 also sends the effective
policy from server to EVERY player on joining or changing settings via a
command. A client-side sound filter suppresses recognized hit sounds
near the affected player/NPC when the synchronized server policy says OFF.
Individual clients do not have a private sound switch.

### Optional OP commands for instant changes (no restart)

```
/jjknpc sounds
/jjknpc sounds npc off
/jjknpc sounds npc on
/jjknpc sounds player off
/jjknpc sounds player on
```

All commands require permission level 2. Changes apply server-wide
immediately and are forwarded to currently connected players. Server config
stores the persistent setting.

## Scope and caveats
- These toggles apply to *identified JJK hit/reaction sounds*, **not all JJK
  audio** and not Minecraft's normal death/hurt sounds.
- A hit sound generated at a large offset from its struck entity, or by a
  different upstream sound identifier, might not be suppressed. Report that
  sound with a video/log if it remains audible.
- v0.13 animation integration is unchanged in v0.14. Six-bone Minecraft
  humanoid models cannot necessarily represent the original multi-bone
  player skeleton, so we are **not claiming animation stiffness is fixed**
  without additional, move-specific in-game verification.
- v0.6 NPC-to-NPC melee, custom damage, domains, charge/crouch,
  Kashimo target-locked lightning, grey hair, and editor settings are
  preserved.

## Test
1. Back up world; remove older compatibility addon and install this JAR.
2. Run `/jjknpc version`, verify **v0.14**.
3. As OP, run `/jjknpc sounds npc off`. Hit an NPC: no identified JJK
   hit sound should be audible to anyone. Hit a player: JJK hit sounds
   should still play while player toggle is ON.
4. Run `/jjknpc sounds player off`, then attack a player. Neither
   category should produce those sounds.
5. Restore one or both by switching `on`.
6. Verify with two connected player clients if possible.

Forge build success is not an actual multiplayer sound/animation test.
