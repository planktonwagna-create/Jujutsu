# Jujutsu NPC Compatibility v0.7 — timing editor test build

**Replaces addon cursed-energy gating with cooldowns in seconds.**
This retains the v0.6 NPC-to-NPC duel targeting and melee-damage fix.
Healing strength remains 1 HP/second while RCT is active; the new settings
control WHEN it may heal, not HOW MUCH it heals per tick.

## Editor pages
`/give @s jujutsunpccompat:editor_tool`, right-click a compatible NPC.

1. **Techniques** — choose a technique and cycle each move between Disabled,
   Automatic, Triggered, and Both. This includes Domain Expansion where available.
2. **Move Timing** — use Previous Move / Next Move to select ANY move from the
   chosen technique. Type an integer **Cooldown seconds (0–3600)** and
   **Charge seconds (0–120)** into the fields. Charge delays the original
   JJK procedure *before* its execution sequence; it does NOT replace the
   original intrinsic animation or technique-specific multi-tick procedure.
3. **RCT & Recovery** — enable/disable RCT; editable **Active seconds (1–600)**
   and **Cooldown seconds (0–3600)**. A fresh active window begins on first
   injured tick after cooldown, healing once per second for at most its window;
   the cooldown starts after the active window. Existing native CustomNPCs
   regeneration and any other mod's healing are unaffected.
4. **Anti-Domain Timing** — select Simple Domain / Falling Blossom Emotion /
   Domain Amplification / Hollow Wicker Basket. Each has an enabled toggle and
   independent **Cooldown seconds (0–3600)**. The original v51 effect is
   applied for 5 seconds and the configured cooldown begins on activation.
   Hollow Wicker Basket is not registered as an effect in v51; its editor
   slot is present but activation remains unsupported.
5. **Domain Variant** — **Malevolent Shrine only** offers Open / Closed.
   JujutsuCraft v51 chooses its open-barrier path via its original Sukuna
   effect check. The addon temporarily adds or hides that exact effect during
   Shrine's domain procedure, restoring the prior effect state immediately
   afterwards. This is EXPERIMENTAL; test both barrier outcomes in-game.
   Do not assume domains other than Shrine support an open choice.
6. **Combat** — preserves automatic combat, idle position, and damage controls.

**Save & Close** or navigate between tabs to commit edited seconds. Settings
are per NPC and saved in persistent NBT. When opening an existing configured
NPC from v0.6, enabled moves are preserved and cooldowns default to their
previous tick values rounded UP to seconds. Default charge=0 seconds.
Default RCT=8 seconds active, 20 seconds cooldown; default defense cooldown=15s.
Domain cooldown defaults to 60 seconds. Cooldown begins after a completed
cast sequence; automatic and manual commands share the same timer.

There is NO addon cursed-energy cost for any move, domain, anti-domain, RCT,
or fatal recovery. Some original JujutsuCraft procedures may still independently
enforce their own native restrictions (player variables, energy, etc.) and
therefore fail to work on an arbitrary NPC.

## Testing
1. Back up a test world, remove v0.6 addon JAR, install v0.7 only.
2. Select Shrine, set Dismantle and Domain to Both, set move cooldowns to
   4 seconds and 20 seconds, respectively, and charges to 1 and 3 seconds.
3. Set RCT Active=5 and Cooldown=15. Set each desired anti-domain cooldown.
4. Confirm the v0.6 `/jjknpc duel <first> <second>` command still allows
   both NPCs to deal melee damage.
5. Test the domain with Open, then Closed, on disposable terrain.
   This can alter the Minecraft world; use a BACKUP.
6. `/jjknpc inspect <npc>` shows charging vs casting; look in `latest.log`
   for exceptions. A compiled JAR is not proof every native JJK cast works.

This addon is a third-party compatibility project; original JujutsuCraft,
Easy NPC and CustomNPCs JARs are not edited.
