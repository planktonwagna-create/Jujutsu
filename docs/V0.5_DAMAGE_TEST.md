# v0.5 combat-damage experiment

Minecraft 1.20.1 / Forge 47.4.26 / JujutsuCraft v51 / Easy NPC 7.15.0 / CustomNPCs GBPort.

The native mod JARs remain unmodified.

## What this addresses
- Easy NPC's **PathfinderMobRaw.isInvulnerableTo** rejects hits because its native
  CombatAttributes default to invulnerable and not attackable by players.
  An optional mixin changes that result for hits from other compatible NPCs or
  players when the *victim* is explicitly configured to allow combat damage.
- CustomNPCs' **EntityNPCInterface.hurt** rejects player damage when its faction
  is friendly to the player and rejects same-faction CustomNPCs attacks. The
  opt-in mixin reroutes only these rejected hits to vanilla PathfinderMob damage.

## How to test
1. BACK UP YOUR WORLD. Remove older compat add-on JARs before installing v0.5.
2. Use `/give @s jujutsunpccompat:editor_tool` in Creative/OP mode.
3. Right-click **each NPC that should be vulnerable**; open Combat & Movement;
   change **Allow combat damage: true**; save.
4. Hit a configured NPC with your weapon. Test NPC vs. NPC melee damage using
   two NPCs with combat AI configured through their original NPC mod editors.
5. Run `/jjknpc inspect <npc>` and verify health decreases. If it does not,
   send `logs/latest.log`, your NPC type, and the inspect output.

## Scope and limitations
- Opt-in: defaults OFF for every existing and new NPC, to preserve original
  faction protections unless specifically enabled for the victim.
- Only hits with Player or compatible NPC as the **responsible source entity**
  are affected. Environmental damage, self-damage, and unknown sources are not
  bypassed. Some JJK spells use ownerless damage sources and may still require
  separate integration.
- The Easy NPC native invulnerability check is bypassed for the above hits
  but all later vanilla damage logic, armor, invulnerability ticks, damage events,
  deaths, and knockback still apply.
- For CustomNPCs blocked friendly/same-faction hits, native CustomNPCs
  NpcEvent.DamagedEvent and some reaction logic are bypassed. Vanilla/Forge
  damage logic remains. Faction affiliation is never changed.
- This does not make non-hostile NPCs acquire targets. Set native faction and
  attack AI separately. It also does not implement or verify domain clashes.
- This is a COMPILE-TESTED experiment; test the addon's behavior in Minecraft
  before assuming it resolves your particular damage blocker.
