# v0.8 - Visible editor and two independent Malevolent Shrine settings

**No cursed-energy gating.** This update retains all v0.7 cooldown, move charge,
RCT and anti-domain timing behavior and the v0.6 NPC-versus-NPC damage fix.

## Fixed: settings are now visible
The original v0.7 editor used bottom-of-screen Previous/Next navigation,
and its technique list could overlap those controls on small GUI scales.
v0.8 uses six numbered tabs always visible at the TOP:

1. **Moves** — select a technique, choose each move via Previous/Next,
   set its mode (Disabled / Automatic / Triggered / Both).
2. **Move Timers** — select EVERY move (including domain) and type its
   individual cooldown and charge in seconds.
3. **RCT** — enable RCT, set active duration and cooldown independently.
4. **Anti-Domain** — each defense has its own toggle and cooldown.
   Hollow Wicker Basket is listed for consistency but remains unsupported
   by the v51 activation bridge.
5. **Domain** — Shrine only: two INDEPENDENT controls listed below.
6. **Combat** — the v0.6 damage setting, duel targeting, idle positioning,
   and fatal recovery controls.

The Save NPC Settings button is anchored at the bottom of the screen.
Small screens show a paginated one-move-at-a-time layout.

## Two different domain settings
For the **Shrine** technique, open the **5 Domain** tab.

### 1) Barrier: OPEN or CLOSED
The native `DomainExpansionCreateBarrierProcedure` checks for Sukuna's
effect to decide its `cnt2` open/closed path for NPC casters.
The addon provides the effect during the native procedure ONLY for the
selected open type, otherwise suppresses it during that call; it then
restores the caster's previous effect state. This does not change
the Shrine model.

### 2) Shrine Appearance: NORMAL or MUTATED
In JujutsuCraft v51, `MalevolentShrineProcedure` spawns either:
* `jujutsucraft:entity_malevolent_shrine` (original standard model)
* `jujutsucraft:entity_malevolent_shrine_2` (original alternate/incomplete model).

The original procedure selects the model by the caster's health ratio
(above/below half HP). To let creators choose a model **without changing
real health or healing**, the addon registers a tightly scoped Mixin
which overrides only the health-return value at the relevant original
Malevolent Shrine procedure call when a compatible NPC is casting the
configured domain. All actual damage calculations, regeneration,
vanilla health and healing stay unchanged.

Model labels NORMAL/MUTATED correspond to v51's model 1/model 2.
The texture/geometry for model 2 is labelled "malevolent_shrine_incomplete"
inside the original mod JAR. Verify which visual best represents the
intended alternate appearance in your installed v51 game.

**The appearance control is independent of the barrier control**.

## Installation / verification

1. BACK UP YOUR WORLD. Remove any previous `JujutsuNPCCompat` JARs
   including v0.6 and v0.7. Install v0.8 only, in `mods`.
2. Launch Minecraft Forge 1.20.1 with JujutsuCraft v51 and your NPC mods.
3. Run `/jjknpc version` to confirm it says **v0.8**.
   If it does not, the new JAR is NOT loading.
4. Hold the addon-specific editor item:
   `/give @s jujutsunpccompat:editor_tool`
   Right-click your configured CustomNPCs or Easy NPC character.
5. Verify **six numbered tabs across the TOP**.
6. Choose Shrine in Moves, enable Domain (Automatic, Triggered, or Both).
   On the Domain tab choose Open/Closed and Normal/Mutated **separately**.
7. Save and confirm with `/jjknpc inspect <npc>` which reports
   `shrineBarrier` and `shrineAppearance`.
8. Test the domain in a disposable test world; open/closed and both
   appearance selections must be validated in game.

The Forge build and inclusion of the compiled mixin do not by themselves
prove JujutsuCraft performed the requested barrier or spawned the chosen
original model. If different options look identical, send latest.log,
the output of /jjknpc version, and a clip showing the NPC Domain tab.
