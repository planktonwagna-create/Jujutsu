# v0.12 - editor layout, NPC animations, and target-locked Kashimo lightning

Forge 1.20.1 / JujutsuCraft v51 / Easy NPC 7.15.0 / CustomNPCs GBPort.

## Confirmed bug fixes in source

### Editor layout
All editor tabs have independent, non-overlapping vertical positions for:
- selection navigation (up to 99px)
- centered move title (107-111px)
- mode and secondary toggle buttons (130-176px)
- description labels outside buttons
- inputs below their labels (176-267px)
- Save NPC Settings always attached to bottom edge.

**Timers** now separates Edit Damage from cooldown/charge inputs.
**Domain** now separates sure-hit damage editing from HP threshold and
Open/Closed barrier controls.
**Item Moves** displays the selected item skill as a centered (width-limited)
title. Its mode, damage/cooldown toggle and numeric fields have independent
rows instead of overlaying one another.
Combat tab no longer has any Technique Passives toggle.

### Kashimo lightning
There is no longer a Kashimo hit-counter, passive marks, three-hit charge
requirement, or separate passive toggle.

When an NPC configured with Kashimo technique casts original Lightning Strike
(`LightningStrikeProcedure`), the addon checks the Mob's **current, live AI
target**. If no AI target is set, the explicitly supplied command target may
be used. It creates electrical particles and thunder at that one entity
and applies a targeted `mobAttack` hit **directly to that entity only**.
The move's existing configured cooldown and move-damage override are respected.
This is the NPC **target-lock compatibility implementation**, not the original
player ability's charge buildup or full procedural visual effect.
World protection, armor, hurt immunity and Forge damage events still apply;
"always sure-hit" refers to targeting, not armor-piercing invulnerability.
The default damage is 12 HP if no custom damage is set.

### Animations
Several v51 player-animation JSON files declare only **0.25s** lifetimes,
while others declare **180-360s** even though their bone transforms end
after fractions of a second. v0.11 used these lengths directly, making
animations almost invisible or permanently overriding vanilla poses.

v0.12 limits ordinary animation display to **0.8-1.3 seconds**, with a
separate sustained lifetime for held-charge poses. It clamps sampled
keyframes to the original animation's duration. Easy NPC's model-manager
lookup now uses the NPC LivingEntity object directly, caches the model-part
reflection, applies motion after Easy NPC's own model updates, and copies
animation into the humanoid hat, jacket, sleeves, and pants outer layers.
Reflection failures are logged once, rather than silently ignored.

Successful regular NPC melee hits trigger a short JJK punch animation when
there is no active cursed-technique animation.

## Install/test
1. BACK UP your world and remove old compatibility-addon JARs. Install v0.12
   alone. Keep JujutsuCraft v51 and the two NPC mods.
2. Run `/jjknpc version`; it must print **v0.12**.
3. Reopen NPC editor. Review Timers, Domain, Combat, and Item Moves pages.
   Numbers and their labels should never overlap buttons.
4. Give an NPC Kashimo, enable the Lightning Strike skill and set an
   explicit cooldown/damage value. Have it lock onto an enemy and cast.
   The electric hit must target the current opponent without prior melee hits.
5. Retest original NPC-to-NPC combat, Easy NPC, and CustomNPCs humanoid poses.
   Use `/jjknpc animate @e[name=...,limit=1] punch_right` as a direct
   packet/render test.
6. If a move still doesn't animate, share latest.log and a short clip.
   Some non-player GeckoLib/custom skeletons cannot use the humanoid adapter.

No Minecraft gameplay tests were run in CI. Forge compilation and packaged
class checks are NOT proof that every native JujutsuCraft move animates.
